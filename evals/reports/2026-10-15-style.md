# archatlas W8d — restyled skill test (2026-10-15)

## What was run

- **Skill:** the packed release zip of main `bc3a56e`, which has the guide-v4 renderer style (S1) and the rich common templates with visual-hierarchy guidance (S2).
- **Runs:** 12 isolated runs, same harness and isolation as W8b. There were no failures or timeouts.
  - **Scenarios:** S1 shop overview, S2 checkout sequence, S7 voting-app views from the repository, and S8 petclinic ER and deployment.
  - **Hosts:** Claude Code (Sonnet 5.5), Codex (GPT-6.1 Sol) and Pi (Sonnet 5.5).
- **Mode:**
  - S1, S2 and S7 ran in autonomous mode.
  - S8 defines only a guided mode, so it ran guided with its scripted answers.
- **Grading:** the existing grader (`grader/prompt.md`, rsvg renders, never the graded model), plus the addendum `grader/visual-note.md`. The addendum also gives the grader `docs/STYLE.md` and the skill's `principles.md`. It returns `visual` scores 0–3 (overall, hierarchy, zones, readability), a one-line verdict and up to three issues.
- **G2:** not judged for Codex, whose trace cannot show image views.
- **Gallery:** the artifact `archatlas-skill-test-gallery` shows every run's final SVGs inline after sanitising, with host, scenario, scores and verdict. It is built by `evals/gallery.py`.
- **Cost:** runs $5.21 and grading $0.80, a total of **$6.01** against a budget of $8.

## Visual verdict

**The style has landed.** All three hosts used the new components without being told:
- tinted zones with header bands;
- one warm focus card;
- cylinders for stores;
- chips for technology facts;
- badges;
- semantic legends.

Text is measured; there were no clipped or mid-word labels and no style-token legends. Claude Code's S1 and Pi's S8 got the best marks for hierarchy (3).

## Defects

These are seen in the grades and confirmed on the contact sheet of all 23 figures.

1. **Emphasis is misused.**
   - Codex paints several nodes `primary`: three in S1, and all seven entities in S8 ER.
   - Pi's S7 container view highlights two apps.
   - **Fix:** the renderer or `check` could warn when more than one element is `primary`/focus, and the templates' guidance should repeat "exactly one".
2. **Sequence diagrams carry no emphasis and are very tall.** On every host, every lifeline has the same weight. The `alt`/`loop` frames span the full width and are heavy. Long vertical gaps make the text small when the figure is fitted. Codex and Pi have activations or lifelines crossing guard text.
   - **Fix:** the sequence layout should reserve guard and label space, size frames to the participants they involve, and allow a focus lifeline.
3. **Routes still detour.** In 8 of 12 runs the grader names long detours or shared runs: S1 payment and support links, the S7 container results push, S8 alternative-profile links.
4. **Legends are incomplete.** The new zone tints, dashed boundaries, peer blue and badges are often unexplained, or a swatch matches no element (Claude S1, Pi S1, Codex S7 context).
   - **Fix:** the automatic legend should add an entry for each tint and boundary style actually used.
5. **Numbered labels are read as order** on context and deployment views (Claude S1, Pi S1, Pi S8).
   - **Fix:** the guidance should say to number only views where order matters, or the legend should say "numbers identify links".
6. **Duplicate outputs.** Claude's S8 left the same deployment and ER figures under two names (`deploy/diagram.svg` and `deployment-diagram.svg`). The gallery shows both.

## Reproduce

```sh
python3 evals/run_eval.py --hosts <hosts.yaml> --scenario S1 --scenario S2 --scenario S7 --scenario S8 \
    --host claude --arm skill --skill-bundle <archatlas-skill.zip> --skill-rev bc3a56e --out <results>/claude
python3 evals/grade.py --hosts <hosts.yaml> --addendum evals/grader/visual-note.md \
    --addendum docs/STYLE.md --addendum skills/architecture-diagrams/references/principles.md <results>/*
python3 evals/gallery.py <results>/* --out <gallery>/index.html
```

The raw results stay outside the repository.
